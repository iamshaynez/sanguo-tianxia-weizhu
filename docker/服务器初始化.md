## 1. 服务器：部署目录与脚本

```sh
ssh <user>@gb-test
mkdir -p /opt/apps/sanguo
# 本仓库 docker/ 三文件放进去：
#   docker/build-remote.sh    -> /opt/apps/sanguo/build.sh    （受限命令：构建+推送+部署）
#   docker/deploy-remote.sh   -> /opt/apps/sanguo/deploy.sh   （pull 幂等 + up + 冒烟）
#   docker/docker-compose.yml -> /opt/apps/sanguo/docker-compose.yml
chmod +x /opt/apps/sanguo/build.sh /opt/apps/sanguo/deploy.sh

# compose 的 ${ACR_REGISTRY} 由同目录 .env 提供（docker compose 自动读取）：
echo 'ACR_REGISTRY=crpi-xxxx.cn-heyuan.personal.cr.aliyuncs.com' > /opt/apps/sanguo/.env
chmod 600 /opt/apps/sanguo/.env

docker login <ACR_REGISTRY>   # 服务器侧一次（已与 novel-universe 共用登录态）
```

## 2. 服务器：受限部署密钥（专用密钥对，绝不复用其他应用的）

```sh
# 本机生成专用密钥对（无口令）
ssh-keygen -t ed25519 -f ~/.ssh/sanguo-deploy -N '' -C 'sanguo-deploy'

# 服务器 authorized_keys 追加（强制命令接管 build.sh + 关闭一切转发/终端）：
command="/opt/apps/sanguo/build.sh",no-port-forwarding,no-X11-forwarding,no-agent-forwarding,no-pty ssh-ed25519 AAAA... sanguo-deploy

# 私钥全文 -> 仓库 secret DEPLOY_KEY
```

CI 连接时以远程命令传 commit sha，build.sh 经 `$SSH_ORIGINAL_COMMAND` 读取并
校验（只认 40 位十六进制）——该密钥除「构建部署本仓库指定提交」外做不了任何事。

## 4. Cloudflare（由使用者配置，不进仓库）

`san.xiaowenz.com` 经 CF proxy → 源站 80（openresty）→ 容器 `sanguo`。compose 已把
端口只绑回环（`127.0.0.1:18091:80`），对外流量一律走 CF + openresty，不直接暴露公网。
**TLS 由 CF 接管**（当前 Flexible：CF 终结 TLS、回源走 80）——源站不配 443/证书；
若将来切 Full(strict)，用 CF Origin Certificate（免费 15 年），不要在源站自行签证书。

## 6. 接入层（san.xiaowenz.com → 服务）

gb-test 入口是 1Panel 的 **openresty** 容器（占 80/443，无 tunnel，CF 直连源站）：

- **网络**：compose 底部 `networks.default.name=apps, external: true` 使容器加入
  openresty 所在的共享 `apps` 网络（nginx 以容器名 `sanguo:80` 反代）。
- **路由**：`/opt/openresty/conf.d/domains.conf` 追加 san 的 **80 server 块**
  （改动前先带日期备份该文件）。**只有 80**：域名走 CF proxy，TLS 由 CF 接管
  （Flexible 回源走 80），源站不配 443 块、不签证书——服务器上 acme.sh/le.crt
  是其他域名的既有配置，与本域名无关，勿动。
- **CF**：若将来切 Full(strict)，给源站装 CF Origin Certificate（免费 15 年），
  并为 san 单独补 443 块；不要用 acme.sh 给 CF-proxied 域名做 HTTP-01 签证书。

# 三国：天下为注

纯前端离线网页游戏：加载后无后端，本地直接玩。

**史书只写了沙场，没写牌桌。** 你捡到一部残卷《英雄记》，记的是另一部三国——乱世英雄，白天争天下，夜里赌江山。每翻一页，乱世就重来一次；赢下牌局，就改写一段遗憾。集齐二十枚野史朱印，写卷人会在最后一页等你。

## 运行

```bash
npm start
# 打开 http://127.0.0.1:8619/
```

`npm start` 会先写入 `runtime.json`，再启动静态服务器。页面右下角显示版本号、提交短 SHA 和本次服务器启动时间（UTC），便于判断当前打开的是哪次部署；旧服务若显示“启动时间未登记”，说明没有按新方式启动。该文件已加入 `.gitignore`，不需要提交。

## 玩法与剧情

- **残卷四卷三十二回 + 最后一页**：每回都有独立冷开场、本回目标、故人名单、章节专属行军场景、牌局拍点、胜负双结局与下一页钩子。不是只换一句题记。
- **史实底稿与逐战战书**：每回标明公元纪年、史籍／演义来源与改编边界；普通遭遇、关底、多人、连战每一阵、长坂再战和随机外传，都在牌局前展开战书，写清对手、缘由、胜后所得与败后代价。
- **写卷人主干**：白门楼、华容、麦城、五丈原等选择会流进后页，改变人物对白、入场态度和剧情。胜利后可直接续读下一回；终章可封卷、还史或撕卷，撕卷通向无终稿。
- **44 名历史角色**：刘备、关羽、张飞、赵云、典韦、陈宫、貂蝉、孙权、鲁肃、庞统、黄忠、马谡、王平、姜维等加入。可靠本地《三国志9》编号头像逐一对照；少数无可靠独立头像的守将明确使用通用武将像，不错配他人。
- **故人真的记得你**：同一武将重逢时会读取此前胜负、选择和列传记录。白门楼影响煮酒，华容影响麦城与归晋，麦城影响夷陵、白帝城，空城与五丈原影响高平陵。
- **德州扑克即战斗**：单挑短局，也支持真正的同桌 1v2／1v3。每位敌将独立军资、手牌、人格、破绽、情绪和行动；支持按钮与盲注轮换、多人下注、主池／边池、平分、淘汰和筹码守恒。
- **明确的全压与退回**：全压按钮显示全部剩余筹码，只在真正可全压下注时出现；行动后展示投入金额与剩余 0。超过对手跟注能力的部分按规则退回，并在结算中注明，不把退款误作未下注。
- **七场同桌多人关**：凤仪亭、白门楼、长坂坡、舌战、赤壁、定军山、麦城。赤壁为曹操／周瑜／诸葛亮三方同桌；敌将之间也会彼此赢取军资，所有敌将离席才获胜。
- **named 连战**：千里走单骑依次迎战孔秀、韩福、卞喜、王植、秦琪；三顾前两顾即使失利也会继续，第三顾才揭示卧龙真正要考的是什么；七擒孟获每阵都有态度变化。战书返回后再入会续接当前阵，不重刷军资或剧情。
- **破绽**：每名对手有签名破绽，可能是假动作。席位直接显示当前动作，摊牌后破绽簿验证判断；列传记录见过几次、识破几次。
- **攻心／观星**：每手一次。多人局先点击席位选目标，再施放；只影响选中的武将。五丈原改写后解锁“执子之手”，攻心化为观星。
- **天时**：开卷三选一（粮草／夺气／看破／劫营），决定本回起手策略。
- **兵败也产内容**：失败会写回原卷，并留下本回“史鉴”：解释真正看错了什么，重开时提供新的机制提示或天时效果，不直接送胜。
- **大关机制**：白门楼困兽、长坂坡七进七出、麦城白衣全谎、五丈原秋风起等专属规则与开场演出。
- **残卷无终稿**：通关后开放随机外传页，只计胜场，不占正卷。
- **验牌**：每手牌由种子洗牌，战斗中可回放整副牌序。写卷人规矩一：牌可验。

## 开卷与界面

- **四短节开卷**：说明读卷人的身份、史籍与演义边界、胜负与史鉴、牌局目标、破绽／攻心／天时／行军；每次翻页都有淡出收拢与展开淡入，连点不会越过内容，减少动态效果时直接换文。可跳过，目录可重温。天时、地图、下注、破绽和攻心另有第一次真实操作时的情境提示。
- **史诗展卷**：战书以卷轴杆、纸面展开、朱印和本地立绘构成入场仪式；信息不会因加速而省略，“略过展卷”只结束装饰动画。移动端使用不裁文字的淡入，正文和按钮均避开两侧卷轴杆及底部安全区。支持键盘焦点、Escape 返回、减少动态效果与手机独立滚动。
- **章节专属入场**：战书确认后才进入武将卡。武将卡包含本地头像、章节小传、旧账台词、本回战法与真实六维；多人关逐将亮相，重复挑战不重复播放入场，新条件版本仍会出现。
- **席位化牌桌**：头像、姓名、军资、情绪、签名破绽和详情入口都归属于各武将席位。多人局当前行动者自动居中，窄屏可横向滑动；点击席位选择攻心／观星目标，点“谱”查看完整武将卡。
- **三国古风 UX**：开卷 → 史实底稿／冷开场 → 天时 → 行军见闻 → 战前展卷 → 武将亮相 → 对局 → 朱批结算／续读下一回。
- **观阵录**：同一套立绘与六维用于入场和列传，展示战绩、出场回目与识破记录；刷新后保留。
- **响应式与可访问性**：桌面与窄屏分别排布，章节正文独立滚动、底部操作区固定并适配手机安全区；移动端保留横排行动按钮，支持键盘节点、减少动态效果和演出加速。
- **部署版本页脚**：右下角展示版本号、提交短 SHA 与服务器启动时间（UTC），首页和 `runtime.json` 禁用缓存；旧部署会明确提示“启动时间未登记”。

## 开发

```bash
npm run lint:content  # 章节、剧本、人物、阵容与头像配方校验
npm run eval:ai       # AI 行为评估 + 多人规则与随机筹码守恒
npm run test:e2e      # 用户视角 E2E 全套件（Playwright）
npm test              = 内容校验 + 评估 + E2E
```

## 分支与协作

完整开发、提交、测试和 PR 规范见 [CONTRIBUTING.md](CONTRIBUTING.md)。远程仓库：[iamshaynez/sanguo-tianxia-weizhu](https://github.com/iamshaynez/sanguo-tianxia-weizhu)。

- `main` 为稳定分支，`dev` 为日常集成分支。
- 功能开发从 `dev` 切专题分支，先通过 PR 合入 `dev`；发布时再通过 PR 将 `dev` 合入 `main`。
- 两个分支均禁止直接推送、删除和强制推送，只允许 PR 合并；所需审核人数为 0，但仍须完成自审、完整测试和 CI。
- PR 自动运行 `.github/workflows/ci.yml` 的完整 `npm test`；UI 改动还须附桌面、手机及涉及布局的实际截图。

测试哲学与 TDD 工作流见 [TESTING.md](TESTING.md)：只为用户可见行为写 E2E，不写内部实现的单元测试；AI 行为改动必须先过评估套件；章节与剧本是数据，数据有测试。

调试参数：

- `?seed=固定种子`
- `?fast=演出加速`
- `?chips= / ?opp= / ?bossopp=筹码`；多人可用 `?bossopp=500,600,700` 分席覆盖，单值则覆盖全部敌将
- `?chapter=回目id 直达`
- `?omen=fx 预选天时`
- `?stage=boss 直达关卡`
- `?node=m1 直达指定行军节点`
- `?round=5 直达连战轮次`
- `?intro=1 强制重播入场`
- `?tutorial=0/1 关闭或强制开卷引导`
- `?traits=武勇,智谋,诈术,胆识,耐性,心性(0..100)` 人格属性包

## 人格基座

对手的牌风由六维三国语义属性驱动（`src/persona.js`）：**武勇**（进攻／价值打薄）、**智谋**（读人／连环／借题）、**诈术**（诈唬／半诈唬／假破绽）、**胆识**（抗压）、**耐性**（慢打／跟注火候）、**心性**（情绪稳定／激将相性）。每个维度都真实改变牌局。

胜率判断与人格分离：单挑翻牌前查 169 类离线胜率表，其余局面做可复现蒙特卡洛模拟，并显式传入当前存活对手数。接近底池赔率边界时提高精度；多人平分按实际并列人数计算底池份额。

## 内容即数据

- `src/chapters.js`：年号、地名、规则、阵容与天时。
- `src/story-data/scroll-*.js`：四卷与终章完整剧本。
- `src/story-data/briefings.js`：33 回史实底稿、改编说明、逐战战书与连战分阵文本。
- `src/story-engine.js`：条件、场景、入场、拍点和结局解析。
- `src/generals.js` / `src/portrait.js`：武将档案、台词、签名破绽与头像映射。
- `src/encounters.js`：单对手、同桌阵容与 named 连战归一化。

配方由 `tests/content/chapters.lint.mjs` 把守：全部 33 回必须有完整剧本、史实底稿和两类战书，连战必须逐阵覆盖；人物和场景引用必须有效，多人阵容为 2–3 名对手，连战配置与轮次一致。

## 设计笔记

第一版是 3D（Three.js），教训：小团队做“精致 3D”性价比极低，人物模型的廉价感会毁掉氛围。2D/2.5D 把“精致”转移到字体排印、平面插画、人物文本和 CSS 动效上——暮色当铺的案底在 `archive-3d/`。

# 三国：天下为注

纯前端离线网页游戏:加载后无后端,本地直接玩。

**史书只写了沙场,没写牌桌。** 你捡到一部残卷《英雄记》,记的是另一部三国——乱世英雄,白天争天下,夜里赌江山。每翻一页,乱世就重来一次;赢下牌局,就改写一段遗憾。

## 运行

```bash
python3 -m http.server 8619
# 打开 http://127.0.0.1:8619/
```

## 玩法

- **残卷四卷三十二回**:每回一场著名战役的"另一种可能"——宛城救典韦、麦城保荆州、五丈原借命。年号题记、地名行军图,通关一遍约等于打了一遍三国编年史。
- **武将出场**:22 名历史武将,四次照面——先闻其名(题记),再见其人(武将卡/牌风),三见其性(签名破绽/台词/造型),四留其名(列传)。吕布、卧龙等名将均使用本地《三国志9》原版头像。
- **德州扑克即战斗**:单挑短局,盲注定期上涨,一手一手把对手清台。
- **破绽**:每个对手有自己的签名破绽(15% 是假动作,兵不厌诈),图鉴记录你的"观阵"心得;列传记下你见过几次、识破几次。
- **攻心**:每手一次激将。对手是否上钩,由他的心性决定——张飞一点就着,司马懿不动如山。
- **大关机制**:白门楼困兽、长坂坡七进七出、麦城白衣全谎、五丈原秋风起——大关回各有专属规则与开场演出;每个关卡都有入场一瞬。
- **页间因果**:你改写的历史会流进后面的页——麦城既改,夷陵的题记随变。精选因果对,不是模板。
- **执子之手**:改写五丈原后解锁——亲手执丞相之名再战一场,攻心化为观星。
- **残卷无终稿**:通关后开放,随机外传页无限续玩(随机武将/地名/规则/天时),只计胜场不占正卷。
- **天时**:开卷三选一(粮草/夺气/看破/劫营),一拍即定。
- **兵败也产内容**:输了,正史写进你的残卷,写卷人留一句批注;赢了,野史盖上朱印。终局门槛看改写率。
- **写卷人**:大关回全部改写 + 野史满二十,最后一页浮现——你一直在和叙事者对赌。
- **验牌**:每手牌由种子洗牌,战斗中左下角可回放整副牌序。写卷人规矩一:牌可验。

## 界面与武将卡

- **三国古风 UX**:以老《三国志》的卷轴、地名地图、半身武将和能力值为构图参考,重做开卷 → 残卷 → 题记 → 行军 → 对局 → 朱批结算的完整视觉动线。绢图上有山川、河流与朱色军令,牌桌使用漆木、军绿布面与铜件。
- **每个对手都有亮相**:遭遇战是短卡,关卡是完整武将卡;无名部曲与守将也使用原版通用头像。点击「交锋/应战」可立即跳过,连战不重复播放入场;亮相和战斗期间军令防连点重入。
- **卡面就是战前情报**:本地《三国志9》头像、姓名、小传、开场白、本回战法与真实六维同屏;六维直接对应 AI 战术,不是装饰数值。大关使用朱红关卡印。
- **观阵录复用卡面语言**:同一套立绘和六维组件用于入场与列传,刷新后仍保留战绩和识破记录。
- **席位化牌桌**:头像、姓名、军资、情绪、台词和详情入口都归属于各自武将席位;点击席位「谱」可查看完整武将卡。`setPlayers` 可生成多个对手席位,狭窄屏幕横向滑动,当前行动者自动居中,公共牌区与己方手牌不随人数重排。当前游戏规则仍为一对一,多人席位是 UI 兼容层,不代表已实现联网或多人规则。
- **响应式**:桌面与窄屏分别排布武将卡和帐中 HUD;移动端保留横排行动按钮,名牌不压手牌。头像为本地 JPG,其余视觉资源由本地 SVG/CSS/Canvas 生成,无外部图片依赖。

## 开发

```bash
npm run lint:content  # 章节配方校验(~0.5s)
npm run eval:ai       # AI 行为评估(33 场景,~2s)
npm run test:e2e      # 用户视角 E2E 全套件(Playwright,~15min)
npm test              = 内容校验 + 评估 + E2E
```

## 分支与协作

远程仓库：[iamshaynez/sanguo-tianxia-weizhu](https://github.com/iamshaynez/sanguo-tianxia-weizhu)。

- `main`：稳定分支；`dev`：日常集成分支，两者从同一初始提交建立。
- 功能开发从 `dev` 切功能分支，先通过 PR 合入 `dev`；发布时再通过 PR 将 `dev` 合入 `main`。
- `main` 与 `dev` 均启用保护：禁止直接推送、删除和强制推送，只允许 PR 合并；所需审核人数为 0。

测试哲学与 TDD 工作流见 [TESTING.md](TESTING.md):只为用户可见行为写 E2E,不写内部实现的单元测试;AI 行为改动必须先过评估套件;章节是数据,数据有测试。

调试参数:`?seed=固定种子` `?fast=演出加速` `?chips= / ?opp= / ?bossopp=筹码` `?chapter=回目id 直达` `?omen=fx 预选天时` `?stage=boss 直达关卡` `?traits=武勇,智谋,诈术,胆识,耐性,心性(0..100) 人格属性包`。

## 人格基座

对手的牌风由六维三国语义属性驱动(`src/persona.js`):**武勇**(进攻/价值打薄)、**智谋**(读人/连环/借题)、**诈术**(诈唬/半诈唬/破绽作假)、**胆识**(抗压)、**耐性**(慢打/跟注火候)、**心性**(情绪稳定/激将相性)。每个维度都真实改变牌局(由 ai-eval 统计证明),任何角色只是一包六维数值。战斗运行时还有士气事件流:爆冷、连败、大胜、激将都会改变对手状态。

## 内容即数据

《英雄记总目》(`src/chapters.js`)与武将档案库(`src/generals.js`):33 回章节、22 名武将,全部是纯数据。加一回 = 加一条章节数据;加一个武将 = 加一条档案(签名破绽/台词/小传/造型键),章节以 `boss.gen` 引用、跨回复用、境遇只改属性。配方由 `tests/content/chapters.lint.mjs` 把守。

## 设计笔记

第一版是 3D(Three.js),教训:小团队做"精致 3D"性价比极低,且人物模型的廉价感会毁掉整个氛围。2D/2.5D 把"精致"转移到字体排印、平面插画和 CSS 动效上——暮色当铺的案底在 `archive-3d/`。此后定调三国:架空世界要文笔,三国只要会玩梗。
